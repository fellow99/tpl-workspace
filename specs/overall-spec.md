## 一、系统定位

「tpl-workspace」是一个**多端业务应用框架**，提供跨平台（Web / Android / HarmonyOS / 微信小程序）的业务应用开发底座。框架内置用户注册、登录、个人中心等基础账号能力，通过「管理后台继承成熟框架 + 用户侧独立轻量」的双轨架构，支持快速搭建各类多端业务系统。

### 1.1 目标用户

| 角色 | 说明 |
|------|------|
| **终端用户** | 使用业务应用的注册用户 |
| **管理员** | 管理系统配置、维护用户 |

### 1.2 核心能力

- **用户账号体系**：注册、多方式登录（密码/短信/微信）、个人中心、验证码
- **多端覆盖**：Web + Android + HarmonyOS + 微信小程序，模块编号跨端对齐
- **框架继承**：管理后台继承 RuoYi-Vue-Plus，用户侧独立轻量工程
- **安全基线**：BCrypt 密码加密、AES+RSA 传输加密、Sa-Token 认证

> **桌面工作台（前端门户）**：本仓库还包含统一的「桌面工作台」前端门户模块 —— `tpl-desktop`（多页面可视化桌面应用，wujie 微前端宿主）与 `tpl-desktop-plugin-demo`（wujie 微前端子应用插件示例），纯前端、无后端。其功能规格（模块占位、功能、设计）见各自 `specs/` 目录，不在本文档（多端业务框架）范围内。

## 二、系统边界

### 2.1 范围内

- 用户注册、登录（密码/短信/微信）、个人信息管理

- 多租户
- 支付/订阅体系

## 四、用户故事

### 4.1 用户模块

- 作为用户，我可以使用用户名+密码注册账号，以便获得个性化服务。
- 作为用户，我可以使用密码/短信/微信三种方式登录，以便快速进入应用。
- 作为用户，我可以管理个人信息（昵称、头像、手机号、邮箱），以便保持档案准确。

## 五、功能需求（按领域）

### 5.1 用户注册及登录（FR-002）

- FR-002-001: 系统 MUST 支持用户名+密码注册。
- FR-002-002: 系统 MUST 支持密码登录、短信免密登录、微信登录三种方式。
- FR-002-003: 系统 MUST 提供图形验证码，防止暴力破解。
- FR-002-004: 系统 MUST 使用 BCrypt 加密存储密码。
- FR-002-005: 系统 SHOULD 支持 AES+RSA 加密传输登录/注册请求。
- FR-002-006: 系统 MUST 支持微信账号绑定/解绑（复用 sys_social 表）。

---

## 六、非功能需求

| 类别 | 需求 |
|------|------|
| **性能** | 分页查询 < 500ms |
| **安全** | 密码 BCrypt 加密、JWT 签名、AES+RSA 传输加密、生产环境强制验证码 |
| **多端一致** | 各平台遵循 DESIGN.md 设计系统 |
| **可维护** | 框架继承不复制，业务表 `tpl_*` 与框架表 `sys_*` 隔离 |
