## 一、样本分析：RuoYi-Vue-Plus 的用户体系

### 1.1 认证架构

RuoYi-Vue-Plus 使用 **Sa-Token**（非 Spring Security）作为认证框架，核心模式：

```
客户端请求 → AuthController → 校验 ClientId + GrantType → 策略分发 → Sa-Token 签发 Token
```

**关键设计点**：

| 设计 | 实现 |
|------|------|
| 统一登录入口 | 所有登录方式走 `POST /auth/login`，通过 `grantType` 区分策略 |
| 策略模式 | `IAuthStrategy` 接口，5 个实现：password / sms / email / social / xcx |
| 客户端控制 | `sys_client` 表控制各端可用的 grantType（如 pc=password,social，app=password,sms,social） |
| 第三方绑定 | `sys_social` 表，解耦第三方账号与系统用户，支持一个用户绑定多个平台 |
| 多租户 | 通过 `tenantId` 动态切换数据源 |
| 注册开关 | `sys_config` 键 `sys.account.registerUser` 控制 |
| 传输加密 | AES 加密 body + RSA 加密 AES key（登录/注册请求） |

### 1.2 用户表核心字段（`sys_user`）

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | bigint | 主键 |
| dept_id | bigint | 部门 ID |
| user_name | varchar(30) | 用户名（登录账号） |
| nick_name | varchar(30) | 昵称 |
| user_type | varchar(2) | 用户类型（sys_user=系统用户） |
| email | varchar(50) | 邮箱 |
| phone_number | varchar(11) | 手机号 |
| sex | char(1) | 性别 |
| avatar | varchar(200) | 头像路径 |
| password | varchar(100) | BCrypt 加密密码 |
| status | char(1) | 状态（0正常 1停用） |
| del_flag | char(1) | 删除标志 |
| login_ip | varchar(128) | 最后登录 IP |
| login_date | datetime | 最后登录时间 |

### 1.3 请求/响应模型

```
LoginBody（基类）
├── clientId, grantType, tenantId, code, uuid
│
├── RegisterBody（注册）: username, password, userType
├── PasswordLoginBody: username, password
├── SmsLoginBody: phoneNumber, smsCode
├── SocialLoginBody: source, socialCode, socialState
└── XcxLoginBody: xcxCode

LoginUser（Sa-Token 会话主体）
├── userId, username, nickname, userType, tenantId
├── roles[], permissions[], posts[]
├── clientKey, deviceType, deptId
└── getLoginId() = "userType:userId"
```

### 1.4 适合本产品复用的部分

| 复用 | 说明 |
|------|------|
| Client + GrantType + Strategy 策略体系 | 完整复用，无需自己造轮子 |
| `sys_social` 第三方绑定表设计 | 直接复用，适配微信绑定与登录 |
| Sa-Token + LoginHelper 登录体系 | 直接复用 |
| AES+RSA 加密传输机制 | 直接复用 |
| 验证码（图形码 + 短信码）生成/校验 | 直接复用 |

### 1.5 需要精简的部分

| 精简 | 原因 |
|------|------|
| 多租户（tenantId） | tpl-workspace无多租户场景，去掉 |
| 部门/岗位（dept_id / post） | 用户端不需要组织架构 |
| 用户类型（sys_user） | 只有用户一种角色 |
| 邮箱验证码登录 | MVP 阶段不需要 |

### 2.2 数据库命名规范

| 类型 | 格式 | 示例 | 说明 |
|------|------|------|------|
| 业务表 | `tpl_<功能名称>` | `tpl_user_profile`、`tpl_error_question` | 全小写，下划线分隔 |
| 业务视图 | `tpl_<功能名称>_view` | `tpl_user_view`、`tpl_error_question_view` | 糅合 RuoYi 标准表与本产品业务表 |

### 2.3 用户表设计：标准表 + 扩展表 + 视图

**设计原则**：RuoYi-Vue-Plus 标准表（`sys_*`）不做任何修改，避免连锁改动，便于后续升级框架。

```
                 sys_user (RuoYi 标准表 — 不改动)
                ┌──────────────────────────┐
                │ user_id    (PK)          │
                │ user_name                │
                │ nick_name                │
                │ phone_number              │
                │ password                 │
                │ avatar                   │
                │ status / del_flag        │
                │ login_ip / login_date    │
                │ dept_id / user_type ...  │ ← RuoYi 标准字段，保留但不使用
                └──────────┬───────────────┘
                           │ 1:1
                           ▼
              tpl_user_profile (本产品扩展表)
              ┌────────────────────────────┐
              │ profile_id  (PK)           │
              │ user_id     (UNIQUE FK)    │──▶ sys_user.user_id
│ birth_date                │  ← 出生日期（选填）
│ create_time               │
              │ update_time               │
              └────────────────────────────┘
                           │
                           ▼ (JOIN 生成)
                   tpl_user_view (视图)
              ┌────────────────────────────┐
              │ user_id, user_name,        │
              │ nick_name, phone_number,    │
              │ password, avatar, status,  │
              │ login_ip, login_date,      │
│ birth_date                 │ ← 从 tpl_user_profile 补充
              └────────────────────────────┘
```

**建表 SQL**：

```sql
-- 标准用户表：RuoYi-Vue-Plus 原生 DDL，不做任何改动
-- 来源：RuoYi-Vue-Plus/script/sql/ry_vue_5.X.sql 中的 sys_user

-- 扩展表：本产品业务字段
CREATE TABLE tpl_user_profile (
    profile_id      BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT       NOT NULL UNIQUE,             -- FK → sys_user.user_id
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    update_time     DATETIME     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT fk_profile_user FOREIGN KEY (user_id) REFERENCES sys_user(user_id)
);

-- 视图：tpl-app-api 读写用户信息时使用此视图
CREATE VIEW tpl_user_view AS
SELECT
    u.user_id,
    u.user_name,
    u.nick_name,
    u.phone_number,
    u.password,
    u.avatar,
    u.status,
    u.del_flag,
    u.login_ip,
    u.login_date,
    u.create_time,
p.birth_date
FROM sys_user u
LEFT JOIN tpl_user_profile p ON u.user_id = p.user_id
WHERE u.del_flag = '0';
```

**读写策略**：

| 操作 | 目标 | 说明 |
|------|------|------|
| 注册 | `sys_user` + `tpl_user_profile` | 同一事务中写入两张表 |
| 登录读取 | `tpl_user_view` | 一次查询获取全部字段 |
| 修改个人信息 | `sys_user` + `tpl_user_profile` | 哪张表的字段就写哪张表 |
| 管理员查用户 | `tpl_user_view` | tpl-manage 中同样使用视图查询 |

**tpl-app-api 中的 MyBatis-Plus 映射**：


### 2.4 第三方绑定表

> 注：RuoYi 自带的 `sys_social` 表保持不变。本产品的微信绑定直接使用 `sys_social` 表，通过 `user_id` 关联 `sys_user`。以下为参考设计，实际即复用 RuoYi 表结构。

```sql
-- 复用 RuoYi-Vue-Plus 的 sys_social 表（不做改动）
-- 关键字段：user_id → sys_user.user_id
--          auth_id = source + uuid（唯一索引）
--          source → wechat_open / wechat_mp / wechat_enterprise
```

**设计要点**：
- 直接使用 RuoYi `sys_social` 表，不做任何改动
- 一个用户可绑定多个第三方（微信开放平台 + 微信公众号），一个第三方只能绑定一个用户
- `auth_id = source + uuid` 确保唯一性
- 登录时通过 `auth_id` 查找绑定关系 → 获取 userId → 从 `tpl_user_view` 读取用户信息 → 签发 token

### 2.5 客户端配置

直接使用 RuoYi 的 `sys_client` 表（不做改动）。种子数据示例：

| client_id | grant_type | device_type | 说明 |
|-----------|-----------|-------------|------|
| web | password,sms,social | pc | 网页端 |
| app | password,sms,social | app | Android/鸿蒙端 |
| mini | xcx | mini | 微信小程序端 |

## 三、业务功能规格

### 3.1 注册（register）

```
POST /auth/register
Content-Type: application/json
Encrypt: AES+RSA

Request:
{
    "username": "zhangsan",
    "password": "******",
    "phonumber": "13800138000",    // 可选，微信注册时可不填
"code": "abcd",                // 图形验证码
    "uuid": "xxx"                  // 验证码唯一标识
}
```

| 步骤 | 逻辑 | 参考 RuoYi |
|------|------|-----------|
| 1. 注册开关检查 | 检查 `sys_config` 键 `sys.account.registerUser` | `SysConfigService.selectRegisterEnabled()` |
| 2. 验证码校验 | 图形验证码，Redis key `captcha_codes:{uuid}`，5分钟有效 | `SysRegisterService.validateCaptcha()` |
| 3. 用户名唯一性 | `sys_user.user_name` 唯一索引 | `SysUserMapper.checkUserNameUnique()` |
| 4. 手机号唯一性 | 如填写手机号，检查 `sys_user.phone_number` 唯一 | 新增校验 |
| 6. 密码加密 | BCrypt 加密存储 | `BCrypt.hashpw()` |
| 7. 写入数据库 | **同一事务**：insert `sys_user` + insert `tpl_user_profile` | 扩展自 `SysUserServiceImpl.registerUser()` |
| 8. 返回结果 | 注册成功提示，引导登录 | - |

### 3.2 登录（login）

```
POST /auth/login?grantType=password
Content-Type: application/json
Encrypt: AES+RSA

Request:
{
    "clientId": "web",
    "grantType": "password",
    "username": "zhangsan",
    "password": "******",
    "code": "abcd",
    "uuid": "xxx"
}

Response:
{
    "access_token": "sa-token-xxx",
    "expire_in": 7200,
    "client_id": "web"
}
```

**支持三种登录方式**：

#### 3.2.1 密码登录（grantType=password）

| 步骤 | 逻辑 | 数据源 |
|------|------|--------|
| 1. 校验 client + grantType | `sys_client` 表（RuoYi 标准表）验证客户端是否允许 password | `sys_client` |
| 2. 校验图形验证码 | Redis `captcha_codes:{uuid}` | Redis |
| 4. 密码校验 | BCrypt.checkpw | - |
| 5. 登录错误限制 | Redis 计数器，超过阈值锁定 | Redis |
| 7. 签发 Token | Sa-Token `StpUtil.login(userId)` | - |
| 8. 记录登录信息 | 更新 `sys_user.login_ip`、`sys_user.login_date` | `sys_user` |

#### 3.2.2 短信免密登录（grantType=sms）

| 步骤 | 逻辑 | 策略类 |
|------|------|--------|
| 1. 发送短信验证码 | `GET /resource/sms/code?phoneNumber=xxx`，4位数字码，存入 Redis 5分钟 | `SmsAuthStrategy` |
| 2. 登录校验 | Redis 校验 `captcha_codes:{phoneNumber}` | - |
| 3. 查询用户 | 按 `phoneNumber` 查 `tpl_user`，不存在则引导注册 | - |
| 4. 签发 Token | 同密码登录 | - |

#### 3.2.3 微信登录（grantType=social）

| 步骤 | 逻辑 | 策略类 |
|------|------|--------|
| 1. 用户点击「微信登录」| 前端调用 `GET /auth/binding/wechat_open` 获取授权 URL | `SocialAuthStrategy` |
| 2. 微信授权回调 | 微信回调 → 前端 `/social-callback` 路由 | - |
| 3. code 换用户 | `SocialUtils.loginAuth("wechat_open", code, state)` | JustAuth |
| 4. 查找绑定 | `tpl_user_social` 表查 `auth_id = source + uuid` | 同 RuoYi |
| 5a. 已绑定 | 取 userId → 签发 Token | - |
| 5b. 未绑定 | 引导用户：选择绑定已有账号 或 注册新账号（自动创建用户 + 绑定） | **新增流程** |

### 3.3 微信绑定

已登录用户可在「个人中心」绑定/解绑微信：

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/auth/binding/wechat_open` | 获取微信授权 URL |
| POST | `/auth/social/callback` | 授权回调 → 写入 `tpl_user_social` |
| DELETE | `/auth/unlock/{socialId}` | 解除绑定 |

### 3.4 个人信息管理（userProfile）

| 方法 | 端点 | 说明 |
|------|------|------|
| PUT | `/system/user/password` | 修改密码（需旧密码验证） |

### 3.5 短信验证码（smsCode）

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/resource/sms/code?phoneNumber=xxx` | 发送 4 位数字验证码，60 秒内不可重发 |

**实现方案**：
- 与 RuoYi 一致，使用 **sms4j** 库
- Redis 存储：`captcha_codes:{phoneNumber}`，有效期 5 分钟
- 发送频率限制：Redis 存储上次发送时间，60 秒内拒绝重发

### 3.6 验证码

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/auth/code` | 获取图形验证码（base64），返回 `{ uuid, img }` |

实现方案与 RuoYi 完全一致。

## 七、与 RuoYi-Vue-Plus 的差异对照

| 维度 | RuoYi-Vue-Plus | tpl-workspace | 说明 |
|------|---------------|---------|------|
| 认证框架 | Sa-Token | Sa-Token | 一致 |
| 标准用户表 | `sys_user`（不改动） | `sys_user`（不改动）+ `tpl_user_profile`（扩展） | 通过视图 `tpl_user_view` 糅合 |
| 用户查询 | 直接查 `sys_user` | 查 `tpl_user_view` | 视图封装 JOIN，透明获取扩展字段 |
| 用户写入 | 写 `sys_user` | 写 `sys_user` + `tpl_user_profile`（同一事务） | 保持数据一致性 |
| 第三方绑定 | `sys_social` | `sys_social`（不改动） | 直接复用 |
| 客户端配置 | `sys_client` | `sys_client`（不改动） | 直接复用 |
| 系统配置 | `sys_config` | `sys_config`（不改动） | 用于注册开关等 |
| 多租户 | 支持，`tenantId` | 不支持 | 去掉动态数据源切换 |
| 角色权限 | RBAC（部门-角色-菜单） | 用户端无需 RBAC | 仅区分登录态/非登录态 |
| 验证码 | 图形 + 短信 + 邮箱 | 图形 + 短信 | MVP 去掉邮箱 |
| 登录方式 | password/sms/email/social/xcx | password/sms/social | 策略模式完全兼容 |
| 命名规范 | RuoYi 默认 | 业务表 `tpl_*`，视图 `tpl_*_view` | 全小写，与 RuoYi `sys_*` 隔离 |

## 八、实现路径

### 阶段一：基础认证（tpl-app-api + tpl-app-web）
