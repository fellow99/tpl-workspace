## 一、概述

本需求为「tpl-workspace」产品线引入**统一的主题皮肤支持能力**：在父工程建立一套**跨端复用的样式变量定义**（`specs/005-theme/var.md`），作为全产品线所有前端子工程的**颜色单一事实源（Single Source of Truth）**，并设计各子工程基于自身技术栈的主题皮肤落地方案与切换机制。

核心诉求拆解：

| 诉求 | 说明 |
|------|------|
| 样式变量定义文档 | 在父工程 `specs/005-theme/` 创建 `var.md`，以 CSS 样式变量为基础，综合各前端子工程的颜色设计，整理出可跨端复用的变量定义 |
| 用户端各自实现 | tpl-app-web / tpl-app-android / tpl-app-harmony / tpl-app-mini 基于各自技术栈，以 var.md 为基准实现主题皮肤支持 |
| 管理端沿用 RVP 体系 | tpl-manage-ui 沿用 RuoYi-Vue-Plus / RuoYi-Vue-Plus-UI 的既有体系延续实现（不参考 DESIGN.md） |
| 后端无主题需求 | tpl-manage / tpl-app-api 不涉及主题皮肤 |

本文档完成**现状分析 + 方案设计**，落地实现（各子工程代码改动）在方案评审通过后另立任务执行。`var.md` 的正式文件在进入实现阶段时于 `specs/005-theme/` 创建，本文档 §五 给出其内容设计。

### 1.1 关键概念界定

- **样式变量（Design Token）**：以 CSS 自定义属性语法 `--xxx: value;` 表达的颜色令牌，是「语义名 → 色值」的映射。采用**角色命名为主**（`--color-primary` 等），DESIGN.md 色彩名作为别名保留（`--indigo: var(--color-primary)`）。
- **主题皮肤（Theme / Skin）**：一组样式变量的取值集合。本需求支持**两套固定皮肤**：默认「破茧」亮色皮肤 + 「护眼暗色」皮肤（DESIGN.md §2.7 规划的暗色能力，本次一并纳入 v1 范围）。
- **换肤机制（Theme Switching）**：在运行时切换当前生效的变量集合，支持**三态**（浅色 / 深色 / 跟随系统，默认跟随系统），并持久化用户选择到本地。

### 1.2 架构方案（已确认：手工映射）

var.md 作为**唯一规范文档**，各端实现时**手工映射**到原生格式（CSS 变量 / colors.xml / color.json / WXSS 变量），**不引入生成脚本**（与 004-i18n 不同：颜色 token 仅约 30 个、变更低频，脚本化属过度设计）。一致性靠 var.md 规范 + 各端实现后的一次性校验清单兜底。

## 二、RuoYi-Vue-Plus 主题皮肤实现分析

RuoYi-Vue-Plus 的主题皮肤完全由**前端 RuoYi-Vue-Plus-UI** 承担，采用「CSS 自定义属性（Design Tokens）」为唯一事实来源，**后端零参与**。tpl-manage-ui 通过 `@plus-ui` alias 已完整继承该体系。

### 2.1 变量定义层（三层结构）

**第一层：业务 CSS 变量**，按主题分文件：

- 浅色主题 `RuoYi-Vue-Plus-UI/src/assets/styles/tokens/_theme.scss`，变量挂在 `:root`：
  - 菜单/侧栏：`--menuBg:#ffffff`、`--menuColor:#1f2937`、`--menuActiveText:#111827`、`--menuHover:rgba(64,158,255,.12)`、`--subMenuBg`、`--subMenuActiveText` 等
  - 顶栏/表格：`--fixedHeaderBg:#ffffff`、`--tableHeaderBg:#f8fafc`、`--tableHeaderTextColor:#475569`
  - App 壳：`--app-radius-base:14px`、`--app-shadow-sm/md/lg`、`--app-surface-bg`、`--app-surface-border`、`--app-shell-bg:#f5f7fa`、`--app-accent-strong:#409eff`、`--app-accent-soft`、`--app-text-title:#1f2937`、`--app-text-muted:#6b7280` 等
  - Element Plus 桥接：`--el-border-radius-base:var(--app-radius-md)`、`--el-bg-color-page:var(--app-shell-bg)` 等
- 暗色主题 `RuoYi-Vue-Plus-UI/src/assets/styles/tokens/_theme-dark.scss`，在 `html.dark` 选择器下「同名变量覆写」：`--menuBg:#111827`、`--app-shell-bg:#060b16`、`--app-surface-bg:#111827`、`--app-accent-strong:#60a5fa`、`--app-text-title:#f3f7ff`，并直接覆写 Element Plus 组件级变量（`el-button` 各类型、`el-tag`、`el-switch`、`el-table`、vxe-table 暗色变量）。

**第二层：Sass 变量兼容层** `_sass-vars.scss`：旧模块消费的 Sass 变量直接引用 CSS 变量中转（`$base-menu-color: var(--menuColor)`），另保留基础色板 `$color-primary:#409eff`、`$color-success:#67c23a`、`$color-warning:#e6a23c`、`$color-danger:#f56c6c`、`$color-info:#909399`。

**第三层：CSS module 导出** `_exports.scss`（`:export`）+ `variables.module.scss`（`@forward`/`@use` 汇总入口），供 JS/Vue 消费。

### 2.2 切换机制（双 class 体系 + 运行时注入）

**1) 全局亮/暗切换 —— VueUse `useDark` 管理 `html.dark` class**

`src/layout/components/Settings/index.vue`：

```ts
const isDark = useDark({ storageKey: 'useDarkKey', valueDark: 'dark', valueLight: 'light' });
const toggleDark = () => useToggle(isDark);
```

VueUse `useDark` 自动在 `<html>` 上增删 `dark` class 并写入 localStorage，联动 Element Plus 官方暗色变量（`main.ts` 导入 `element-plus/theme-chalk/dark/css-vars.css`）。`_theme-dark.scss` 正是在 `html.dark` 作用域下覆写业务变量，故**暗黑模式 = `html.dark` class 切换 + CSS 变量覆写**。

**2) 侧栏主题（独立维度）**：`SideThemeEnum`（`theme-dark`/`theme-light`），`Sidebar/index.vue` 动态挂 class，只影响侧栏配色，与全局暗黑模式解耦。

**3) 自定义主题色 —— CSS 变量运行时注入 + 8 色预设**

`src/utils/theme.ts` 的 `handleThemeStyle(theme)` 通过 `getLightColor`/`getDarkColor` 算法生成主色的 9 级 light/dark 变体，逐一 `document.documentElement.style.setProperty('--el-color-primary', theme)` 及 `--el-color-primary-light/dark-1..9`，覆盖 Element Plus 主题变量。`App.vue` onMounted 恢复，设置面板 `el-color-picker` 预置 8 色。

### 2.3 持久化机制（纯 localStorage，无后端）

| 数据 | localStorage key | 机制 |
|------|------------------|------|
| 主题色+侧栏+布局全套 | `layout-setting` | VueUse `useStorage` |
| 全局暗黑模式 | `useDarkKey` | VueUse `useDark` |

### 2.4 后端联动结论（重点）

RuoYi-Vue-Plus **后端完全无主题相关实现**：
- `sys_user` 表无任何主题字段（`script/sql/ry_vue.sql` L81-107 列清单确认）
- `sys_config` 无主题相关 key
- 后端 Java/SQL/XML 检索 `theme`/`dark` 零命中
- 前端 `/system/user/getInfo` 返回的用户信息不含主题

结论：**主题为用户浏览器级偏好，纯前端自包含**，无后端存储/接口。

### 2.5 可复用点小结（供 tpl-manage-ui 沿用）

| 复用点 | 位置 | 说明 |
|--------|------|------|
| token 变量层 | `assets/styles/tokens/_theme.scss`、`_theme-dark.scss` | 浅色 `:root` / 暗色 `html.dark` 同名覆写 |
| Sass 兼容层 | `assets/styles/tokens/_sass-vars.scss` | `$xxx: var(--xxx)` 中转 |
| 换肤算法 | `utils/theme.ts` | `handleThemeStyle` + 9 级色阶 |
| 暗黑切换 | VueUse `useDark` + `element-plus/theme-chalk/dark/css-vars.css` | `html.dark` class 机制 |
| 持久化 | `layout-setting`、`useDarkKey` | VueUse useStorage / useDark |

## 五、统一样式变量定义设计（var.md 内容设计）

### 5.1 设计目标与约束

1. **单一事实源**：颜色语义名与色值只在 `specs/005-theme/var.md` 维护一份，各端不重复发明命名。
2. **CSS 变量为基础**：以 CSS 自定义属性语法 `--xxx: value;` 为规范表达，可机械转换到各端原生格式。
3. **符合宪法**：遵循 `specs/constitution.md` 原则 3（camelCase 命名）、原则 8（设计系统统一）；**不 fork RVP 源码**（原则 1）。
4. **覆盖完整**：综合 DESIGN.md 色板 + 各端现状色值，补齐 DESIGN.md 未定义的扩展色（微信绿、占位符等）。
5. **可切换**：同一变量名提供「default（破茧亮色）」与「dark（护眼暗色）」两套取值，支撑皮肤切换。
6. **手工映射**：var.md 为文档型事实源，各端手工映射实现，不引入生成脚本（§1.2 方案 A）。

### 5.2 变量命名规范（角色命名为主 + 色彩名别名）

```
--color[-<域>]-<语义>
```

| 规则 | 说明 | 示例 |
|------|------|------|
| 前缀 | 统一 `--color-` | `--color-primary` |
| 语义段 | kebab-case 英文 | `--color-text-secondary` |
| 色彩名别名 | DESIGN.md 色彩名作为别名保留，映射到角色变量 | `--indigo: var(--color-primary)` |

## 六、各子工程主题皮肤落地方案

> 统一切换机制（决策 D4）：**三态**（浅色 `light` / 深色 `dark` / 跟随系统 `system`，默认 `system`），用户选择持久化本地，切换入口统一放在各端「个人中心/设置」页。

### 6.1 tpl-app-web（Vue 3 SPA，纯 CSS）

2. **皮肤定义**：`style.css` 中 `:root` 挂 default 值，`[data-theme="dark"]` 挂 dark 值。
3. **换肤机制（三态）**：Pinia `appStore` 维护 `theme: 'light'|'dark'|'system'` + `useStorage('theme', 'system')` 持久化；解析逻辑：`system` 时读 `prefers-color-scheme`，`light`/`dark` 时直接 `document.documentElement.dataset.theme = resolved`；监听 `matchMedia('(prefers-color-scheme: dark)')` 变化联动。
4. **首屏防闪烁**：`index.html` 内联脚本在 `<body>` 渲染前读 localStorage 解析三态并设置 `data-theme`，避免暗色用户闪白。
5. **切换入口**：个人中心页新增「外观」设置项（三态单选）。

### 6.2 tpl-app-android（Kotlin + Material Components）

2. **暗色变体**：新增 `res/values-night/colors.xml` 提供 var.md dark 皮肤值；`values-night/themes.xml` 引用暗色资源。
3. **换肤机制（三态）**：`AppCompatDelegate.setDefaultNightMode()` 三态映射——`system`→`MODE_NIGHT_FOLLOW_SYSTEM`、`light`→`MODE_NIGHT_NO`、`dark`→`MODE_NIGHT_YES`；持久化 `SharedPreferences`（复用现有 EncryptedSharedPreferences 或普通偏好）。
4. **清理模板残留**：`side_nav_bar.xml` 茶绿渐变、`ic_launcher` 绿改走 colors.xml 品牌色。
5. **切换入口**：个人中心/设置页新增「外观」三态单选。
6. **映射**：var.md `--color-*` → `color_*`（下划线资源名），命名前缀对齐现有 `tpl_` 约定。

### 6.3 tpl-app-harmony（ArkTS + ArkUI）

1. **收敛硬编码（前置任务）**：将 135 处硬编码色值收敛到 `resources/base/element/color.json`（语义 `name`），12 个 .ets 文件替换为 `$r('app.color.xxx')`。
2. **暗色变体**：新增 `resources/dark/element/color.json` 提供 dark 皮肤值（现有仅 `start_window_background`）。
3. **换肤机制（三态）**：`setColorMode()` 三态映射——`system`→`COLOR_MODE_NOT_SET`、`light`→`COLOR_MODE_LIGHT`、`dark`→`COLOR_MODE_DARK`；持久化 `AppStorage`/`Preferences`；资源限定符自动切换 base/dark。
4. **切换入口**：个人中心/设置页新增「外观」三态单选。
5. **映射**：`--color-primary` → `color_primary`（`name`）。

### 6.4 tpl-app-mini（微信小程序）

1. **品牌色统一**：解决 tabBar `#3B5998` 与页面主色 `#07c160` 的矛盾——页面主色从微信绿迁至靛青 `#3B5998`（微信绿收敛为 `--color-wechat` 仅用于微信登录场景）。
2. **令牌引入**：在 `app.wxss` 定义 CSS 变量（Skyline 支持自定义属性），按 var.md 定义 default/dark 两套。
3. **换肤机制（三态）**：复用 i18n 模式——`config.ts` STORAGE_KEYS 加 `THEME`，`storage.ts` 加 `getTheme/setTheme`，`app.ts` onLaunch 解析三态（`system` 时读 `wx.getSystemInfoSync().theme`）；`app.json` 开启 `"darkmode": true` + `themeLocation` 支持原生暗色适配。
4. **tabBar/导航栏联动**：`wx.setTabBarItem` 改写 tabBar 颜色，`wx.setNavigationBarColor` 改写导航栏（复用 i18n.ts 的 `applyTabBarLocale` 模式）；`wx.onThemeChange` 监听系统深浅变化。
5. **切换入口**：个人中心/设置页新增「外观」三态单选。

### 6.5 tpl-manage-ui（沿用 RVP 体系，不参考 DESIGN.md）

1. **延续现有体系**：暗黑模式与动态换肤已完整继承（`useDarkKey` + `handleThemeStyle`），无需重新设计，保持与 RuoYi-Vue-Plus-UI 一致。
2. **主色处置（决策 D5）**：**保持 Element Plus 默认 `#409EFF` 不变**，不品牌化为靛青（符合需求「沿用 RVP 体系、无需参考 DESIGN.md」）。
3. **收敛本地硬编码色**：login/register 玻璃态渐变、404/401、Sidebar、TopBar、Settings 抽屉等本地视图硬编码色，逐步替换为上游 token 变量（`var(--app-*)` / `var(--el-*)`）。
4. **不 fork 上游**：主题 token（`_theme.scss`/`_theme-dark.scss`）属上游子模块，定制通过 tpl-manage-ui 本地新增样式覆盖（在 `main.ts` 于上游 `index.scss` 之后引入）或 `uno.config.ts`/`settings.ts` 层面注入。

## 七、实施建议与风险

### 7.1 建议实施顺序

1. 在 `specs/005-theme/` 创建 `var.md`（§五 内容定稿），作为各端唯一事实源。
2. 用户端 Web 先行（tpl-app-web）：变量迁移 + 三态换肤 + 首屏防闪烁，打通「变量 → 皮肤 → 切换」全链路。
3. 依次落地 harmony（硬编码收敛 + 资源化）→ android（色值对齐 + 暗色变体）→ mini（令牌引入 + 品牌色统一）。
4. tpl-manage-ui 仅做本地硬编码收敛，主色保持 `#409EFF`，沿用既有体系。
5. 各端实现后补充三态切换与持久化回归（含系统跟随联动验证）。

### 7.2 主要风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| 品牌色矛盾（mini） | tabBar `#3B5998` vs 页面主色 `#07c160` | §6.4 统一为靛青，微信绿收敛为 `--color-wechat`（决策 D2） |
| 品牌色脱节（android） | 主色 `#1976D2` 非设计系统 `#3B5998` | §6.2 色值迁移，清理模板残留（决策 D2） |
| 硬编码收敛成本（harmony） | 135 处硬编码色散落 12 个 .ets | 分文件批量替换，`$r('app.color.xxx')` 资源化 |
| 暗色值未最终定稿 | DESIGN.md 仅给原则未给色值 | var.md §5.7 已给参考值，实现暗色时经视觉 QA 定稿 |
| 上游 token 不可改（manage-ui） | token 在上游子模块 RVP-UI | 本地覆盖，不 fork 上游（宪法原则 1） |
| 三态系统跟随联动 | 各端系统深浅变化监听 API 不一 | 逐端用各自 API（matchMedia / AppCompatDelegate / setColorMode / wx.onThemeChange） |

### 7.3 已确认决策记录

| 编号 | 决策点 | 结论 |
|------|--------|------|
| D1 | 皮肤形态范围 | **亮 + 暗两套固定皮肤**（不预留多皮肤扩展、不做用户自定义主题色） |
| D2 | 品牌主色统一 | **全产品线统一为靛青 `#3B5998`**（mini 微信绿收敛、android 迁移） |
| D3 | 变量命名风格 | **角色命名为主 + 色彩名别名保留**（`--color-primary` 主，`--indigo` 别名） |
| D4 | 换肤交互与持久化 | **三态（浅/深/跟随系统，默认系统）+ 本地持久化**，入口「个人中心/设置」 |
| D5 | tpl-manage-ui 主色 | **保持 `#409EFF` 不变**（沿用 RVP 体系，不品牌化） |
| D6 | 架构方案 | **var.md 文档 + 各端手工映射**（不引入生成脚本） |
