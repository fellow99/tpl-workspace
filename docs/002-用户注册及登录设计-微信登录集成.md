## 一、结论速览

「tpl-workspace」的微信登录需求横跨 **7 个工程**，本质上涉及 **3 种核心机制 + 1 种可选替代（公众号）**：

| 机制 | 官方文档类别 | 授权方式 | 适用工程 |
|------|------------|---------|---------|
| ① 网站应用微信登录（扫码） | 网站应用 | OAuth2.0 授权码（`scope=snsapi_login`），跳转扫码 | tpl-app-web、tpl-manage-ui |
| ② 移动应用微信登录（拉起） | 移动应用 | OpenSDK 拉起微信 App 授权（`scope=snsapi_userinfo`） | tpl-app-android、tpl-app-harmony |
| ③ 小程序微信登录（一键） | 小程序 | `wx.login()` → code → `jscode2session` | tpl-app-mini |
| ④ 公众号网页授权 / 带参二维码（**可选替代**） | 公众号/服务号 | `snsapi_base`/`snsapi_userinfo` 或扫码关注事件 | tpl-manage 的替代方案（需已认证服务号） |

**核心结论**：

1. **前置事务的主体是「微信开放平台」账号运营**，而非代码。三个端侧机制都需要在开放平台（小程序在公众平台）先完成「应用创建 → 资质认证 → 审核通过 → 微信登录能力申请」的完整链条，任何一端缺环都会导致登录失败。
2. **用户端（web / android / harmony / mini）必须绑定到同一个微信开放平台账号**，才能靠 `unionid` 实现「同一微信用户跨端识别」。这是本次集成里**最重要的一个架构决策**，直接影响开放平台上的账号与应用的申请方式。
3. **管理端（tpl-manage / tpl-manage-ui）是另一套账号体系**（管理员 vs 用户），且 tpl-manage 基于 RuoYi-Vue-Plus 6.0.0，**已继承 JustAuth + `sys_social` + `SysSocialController`**，改造量远小于用户端。
4. **tpl-app-api 是独立工程（不依赖 RuoYi），无任何社交登录组件**，需要新增「微信登录策略 + code 换 token 封装 + `sys_social` 绑定 + 授权变更回调」全套能力。
5. 存在**硬性合规与安全约束**：2021-10-20 起微信不再返回性别/地区、头像 URL 会失效需自存、`AppSecret`/`access_token`/`session_key` 禁止进客户端、未上架应用每日限 100 次登录、用户撤回授权后须删除本地数据（消息推送回调）。
6. **公众号方案受账号类型强约束**：网页授权与带参二维码仅限**已认证服务号**，个人订阅号无此能力——若 tpl-manage 不申请服务号，则只能走「网站应用 qrconnect」扫码方案。
7. **个人主体可行方案**：若主体只能为个人，可走「手机号主键 + openid 凭证」方案（§五.5）实现小程序 + 移动端打通，代价是首次双重授权；网站应用/公众号/unionid 打通对个人主体不可行（§三.8）。

## 二、微信登录机制详解

### 2.1 机制①：网站应用微信登录（扫码，OAuth2.0 授权码）

**适用**：tpl-app-web（用户端 Web）、tpl-manage-ui（管理端 Web）。

**流程**：

```
浏览器 ──▶ 跳转 https://open.weixin.qq.com/connect/qrconnect
            ?appid=APPID&redirect_uri=REDIRECT_URI&response_type=code
            &scope=snsapi_login&state=STATE#wechat_redirect
          （用户扫码 → 微信授权页 → 确认）
浏览器 ◀── 回调 redirect_uri?code=CODE&state=STATE
后端  ──▶ GET https://api.weixin.qq.com/sns/oauth2/access_token
            ?appid=&secret=&code=&grant_type=authorization_code
          返回 { access_token, refresh_token, openid, unionid, ... }
后端  ──▶（可选）GET https://api.weixin.qq.com/sns/userinfo
            ?access_token=&openid=   → { nickname, headimgurl, ... }
```

**关键参数约束**：

| 项 | 约束 |
|----|------|
| `scope` | 网站应用**只能填 `snsapi_login`** |
| `state` | 防 CSRF，必须随机 + 服务端校验，原样带回 |
| `redirect_uri` | 域名必须与审核时填写的授权域名一致，否则报「该链接无法访问」 |
| `code` | 有效期 **10 分钟、一次性** |
| `access_token` | 有效期 **2 小时** |
| `refresh_token` | 有效期 **30 天、不可续期**，失效后需用户重新授权 |
| `unionid` | 同一开放平台账号下，同一用户对所有应用唯一 |

**内嵌二维码**：可用官方 `wxLogin.js`（`res.wx.qq.com/.../wxLogin.js`）+ `new WxLogin({...})` 实现页面内嵌二维码，避免整页跳转。

### 2.2 机制②：移动应用微信登录（拉起，OpenSDK）

**适用**：tpl-app-android、tpl-app-harmony。

**流程**：

```
App ──▶ OpenSDK SendAuth.Req（scope=snsapi_userinfo, state）
         拉起微信 App → 用户授权 → 回调 code
App 后端 ──▶ GET https://api.weixin.qq.com/sns/oauth2/access_token
             ?appid=&secret=&code=&grant_type=authorization_code
           返回 { access_token, refresh_token, openid, unionid }
```

**关键参数约束**：

| 项 | 约束 |
|----|------|
| `scope` | 移动应用**只能填 `snsapi_userinfo`** |
| `code` | 10 分钟有效、一次性 |
| `access_token` / `refresh_token` | 2 小时 / **180 天（移动应用，不可续期）** |
| `unionid` | 仅在已获 userinfo 授权时返回 |

> ⚠️ **移动应用与网站应用的 `refresh_token` 有效期不一致**（180 天 vs 30 天），以官方文档为准；二者共同点是「不可续期，失效须重新授权」，因此**身份锚点应使用 `openid`/`unionid`，而非 token**。

**SDK 接入要点（三端差异）**：

| 维度 | Android | HarmonyOS NEXT |
|------|---------|----------------|
| 依赖 | Maven Central `com.tencent.mm.opensdk:wechat-sdk-android:6.8.0` | ohpm `@tencent/wechat_open_sdk`（当前 ~1.0.19） |
| 平台登记字段 | **包名 + 应用签名（SHA1）** | **Bundle ID（=包名）+ Identifier（=appIdentifier）** |
| 回调组件 | `包名.wxapi.WXEntryActivity`（singleTask、**不加 intent-filter**） | UIAbility `onCreate`/`onNewWant` + `WXApi.handleWant(want, handler)` |
| 拉起声明 | `<queries><package com.tencent.mm/></queries>`（Android 11+） | `module.json5` 的 `queryscheme: [weixin, wxopensdk]` |
| 签名失败标志 | `errcode=-6` | 「Bundle ID 信息校验不通过」/「第三方应用信息校验失败」 |

### 2.3 机制③：小程序微信登录（一键）

**适用**：tpl-app-mini。

> 小程序登录走的是**微信公众平台（小程序）**的另一套机制，与开放平台 OAuth 不同（**已补充官方小程序文档**确认，见文末「参考」）。

**流程**：

```
小程序 ──▶ wx.login() → 临时 code（有效期 5 分钟）
后端  ──▶ GET https://api.weixin.qq.com/sns/jscode2session
           ?appid=&secret=&js_code=CODE&grant_type=authorization_code
         返回 { openid, session_key, unionid? }
```

**关键差异**：

| 项 | 网站/移动应用 | 小程序 |
|----|--------------|--------|
| 换取凭证接口 | `sns/oauth2/access_token` | `sns/jscode2session`（`js_code` 参数） |
| 返回核心字段 | access_token + openid + unionid | openid + **session_key** + unionid |
| 是否有 access_token | 有（2h） | **无**，只有 `session_key` |
| unionid 前提 | 绑定开放平台账号 | **小程序必须先绑定到开放平台账号**才返回 unionid |
| 登录态管理 | access_token/refresh_token | 自管业务 token（session_key 仅服务端使用） |

**`session_key` 安全与生命周期（官方）**：

- `session_key` 是对用户数据**加密签名**的密钥，**只应保存在服务端，不下发前端、不对外提供**；
- 同一用户同一时刻**仅有一个有效 `session_key`**；触发 `wx.login` 会生成新 `session_key` 顶替旧的；
- 服务端校验：`GET /wxa/checksession`（`signature = hmac_sha256(session_key, "")`，不传 session_key 明文）；重置：`GET /wxa/resetusersessionkey`（重置后**不续期**，60k 次/分钟）。

**手机号获取（与登录解耦）**：`<button open-type="getPhoneNumber">` → 回调 `e.detail.code`（**5 分钟有效、一次性**，与 `wx.login` 的 code 不同）→ 服务端 `POST /wxa/business/getuserphonenumber?access_token=` → `phone_info`。基础库 2.21.2+ 走新方式（code 换手机号），**不再需要先 `wx.login`**，旧 `encryptedData+iv` 解密方式已废弃。

### 2.4 机制④：公众号网页授权 / 带参二维码（可选替代）

**适用**：tpl-manage 扫码登录的替代方案（当不申请「网站应用」时）。

> ⚠️ **硬约束**：网页授权（`snsapi_base`/`snsapi_userinfo`）与「生成带参二维码」均为**已认证服务号**的能力；**个人订阅号不支持**网页授权、无法生成带参二维码（调接口报 `48001 api unauthorized`）、只能通过事件推送拿到 openid（拿不到昵称头像）。

**两种形态**：

| 形态 | 机制 | 适用 |
|------|------|------|
| 网页授权登录 | `open.weixin.qq.com/connect/oauth2/authorize`，`snsapi_base`（静默只拿 openid）/ `snsapi_userinfo`（用户同意拿资料） | 已认证服务号 |
| 带参二维码「扫码关注即登录」 | `POST /cgi-bin/qrcode/create`（`QR_STR_SCENE` + `scene_str` 携带随机登录码）→ 用户扫码 → 事件推送 `subscribe`/`SCAN`（`EventKey=qrscene_*`/`scene`）→ 按 openid+登录码绑定 | 已认证服务号 |

**关键约束**：

- 网页授权 `appid` **仅支持已认证服务号**（传其他类型报 `10016`/`10003`）；`redirect_uri` 须与后台「网页授权域名」一致；
- 带参二维码 `scene_str` 长度 1~64，临时二维码 `expire_seconds` 最大 30 天；扫码后 `subscribe`（未关注，`EventKey=qrscene_<值>`）与 `SCAN`（已关注，`EventKey=<值>`）事件格式不同，须区分处理；
- 两套机制拿到的都是**同一服务号下的 openid**；要与其他端打通，须将服务号绑定到同一开放平台账号换取 unionid。

## 三、前置条件与前置事务（微信开放平台侧）

> 本节回答「我要在微信开放平台做什么操作、需要什么资质」。以下事务**必须全部完成**，对应端侧的登录才能跑通。

### 3.1 账号与开发者资质认证

> **关键认知**：微信开放平台（open.weixin.qq.com）与微信公众平台（mp.weixin.qq.com）是**两套独立账号体系**。公众号/小程序在公众平台注册，网站应用/移动应用在开放平台创建；跨端身份统一靠「把公众平台账号**绑定**到开放平台账号」实现（绑定后 unionid 才生效）。

| 事项 | 要求 |
|------|------|
| 注册微信开放平台账号 | https://open.weixin.qq.com（邮箱注册，独立于公众平台） |
| 开发者资质认证（企业认证） | **部分应用类目、以及「复用多端应用快速创建」、绑定公众号/小程序均强制要求**；企业内部应用亦需主体认证。企业/组织认证费 **300 元/年**，政府主体免认证费 |
| 主体一致性 | 应用官网主体、应用市场开发者信息、开放平台认证主体**必须一致**；不一致需附授权书（公司双方公章 / 个人签名） |
| 个人 vs 企业边界 | 未认证（个人）账号**不能绑定公众号**、只能绑 5 个同主体小程序、最多建 10 个移动/网站应用；本产品涉及小程序端，**开放平台必须走企业/组织认证** |

**绑定限额（一个开放平台账号，官方）**：

| 对象 | 已认证（组织） | 未认证（个人） |
|------|--------------|--------------|
| 移动应用 / 网站应用 | 50 / 10 | 10 / 10 |
| 公众号/服务号（绑定） | 同主体/关联主体 50 + 异主体 5 | 不支持绑定 |
| 小程序（绑定） | 同主体/关联主体 50 + 异主体 5 | 同主体 5，不支持异主体 |
| 公众号+小程序绑定总量 | 合计上限 100 | — |

> 一个公众号/小程序**只能绑定一个开放平台账号**（互斥）。

### 3.2 创建「网站应用」（供 tpl-app-web / tpl-manage-ui 扫码登录）

**提交材料**：

| 项 | 要求 |
|----|------|
| 应用名称 | ≤10 中文字符 / 20 英文字符，不得含平台/品牌/营销/测试字样 |
| 应用图标 | 清晰、无水印、与名称一致 |
| 应用官网 | **可访问的 PC 官网**（H5/小程序/公众号页面不认可），须含：服务功能详情、**用户协议、版权所有者、网站备案信息（ICP 备案号）、联系方式** |
| 应用流程图 | App 运行截图或交互设计图 |
| 《微信开放平台网站信息登记表》 | 加盖公章（与主体一致），含**规范备案号**（如 `粤ICP备XXX号-1`） |

**审核与能力申请**：

1. 提交「网站应用」创建 → 审核通过 → 获得 AppID / AppSecret；
2. **单独申请「微信登录」能力** → 审核通过后才能接入；
3. 授权回调域名在创建/审核时填写，登录时的 `redirect_uri` 域名**必须与之完全一致**。

> **两个扫码登录端（tpl-app-web 用户端 / tpl-manage-ui 管理端）是两套账号体系，应分别创建独立的「网站应用」**（回调域名不同、后端不同、用户群不同）。详见 §五。

### 3.3 创建「移动应用」（供 tpl-app-android / tpl-app-harmony 拉起登录）

**一个移动应用可同时登记多个平台**（Android + iOS + 鸿蒙），tpl-app-android 与 tpl-app-harmony 建议共用一个移动应用 AppID（便于后端共用同一 AppSecret 换 token）。

**各平台需提交的开发信息**：

| 端 | 必填 | 获取方式 |
|----|------|---------|
| Android | **应用包名（package name）+ 应用签名（SHA1）** | 签名用官方工具 `Gen_Signature_Android.apk` 生成；debug/release 签名须区分 |
| iOS | Bundle ID + Universal Links | （本产品暂无 iOS，可跳过） |
| 鸿蒙 | **Bundle ID（=鸿蒙包名）+ Identifier（=appIdentifier）** | `@ohos.bundle.bundleManager` API 查询 |

**审核与上架状态约束（硬性）**：

| 项 | 约束 |
|----|------|
| 审核 | 1~7 个工作日；**不支持撤回**；驳回后以上一次通过状态运行 |
| 未上架应用 | 微信登录**每日限 100 次**，超限报 `10060` |
| 已上架 | 需提供应用市场链接 + **App 备案号**；Android/iOS/鸿蒙**三端独立开关**，须分别设为已上架 |

### 3.4 小程序注册与绑定（供 tpl-app-mini 一键登录）

- 小程序在**微信公众平台（mp.weixin.qq.com）**注册（邮箱 → 主体类型 → 管理员信息），本产品已有 AppID `wx6f403bf72762b0c3`；
- 主体类型：个人/企业/个体工商户/政府/媒体/其他组织；**个人主体不支持微信认证**（无法申请微信支付）；政府/媒体/其他组织**必须认证**（300 元）；
- **为打通 unionid，须将小程序绑定到与移动应用/网站应用相同的开放平台账号**（开放平台「管理中心 → 小程序 → 绑定」，**前提是开放平台账号已完成开发者资质认证**）；
- 小程序无需「微信登录能力」单独申请（`wx.login` 默认可用）；绑定后 `code2Session` 才返回 unionid。

### 3.5 unionid 跨端打通（关键前置事务）

> 这是「同一微信用户可在 web / android / harmony / mini 四端识别为同一人」的前提。

**身份标识公式（官方）**：

```
openid   = 微信用户 + 单应用 AppID       （每应用不同）
unionid  = 微信用户 + 开放平台账号        （同一账号下所有应用相同）
```

| 前置事务 | 说明 |
|---------|------|
| 统一开放平台账号 | 用户端 4 个应用（1 网站应用 + 1 移动应用 + 1 小程序）必须挂在**同一个开放平台账号**下 |
| 绑定小程序/公众号 | 开放平台「管理中心」绑定小程序/公众号 AppID（需先完成开发者资质认证） |
| unionid 唯一性 | 「同一开放平台账号下，移动应用/网站应用/公众账号（含小程序）的同一用户 unionid 唯一」 |
| 后端持久化 | 后端须保存 unionid（`sys_social.union_id` 字段已具备），登录时按 unionid 优先匹配，其次 openid |

### 3.6 消息推送服务器配置（授权变更合规，必需）

微信要求接收「授权用户信息变更」事件，配置入口为开放平台「管理中心 → 网站应用/移动应用 → 消息推送」。

| 配置项 | 说明 |
|--------|------|
| URL | 接收回调的服务端地址（http/https，80/443 端口） |
| Token | 签名令牌 |
| EncodingAESKey | 消息体加解密密钥（**建议安全模式**：AES-CBC/PKCS#7 + `msg_signature` 验签） |
| 数据格式 | XML 或 JSON |

**必须处理的三个事件**：

| Event | 含义 | 开发者义务 |
|-------|------|-----------|
| `user_info_modified` | 用户资料被平台清理 | 更新/清理本地头像昵称 |
| `user_authorization_revoke`（`RevokeInfo=301`=撤回全部） | 用户撤回授权 | **删除本地用户信息** |
| `user_authorization_cancellation` | 用户注销 | 依法删除个人信息 |

### 3.7 付费提额（可选，量级评估）

| 项 | 数值 |
|----|------|
| 免费额度 | code 换 token **5 万/分钟**；userinfo **5 万/分钟**；refresh **10 万/分钟**；单 openid **180 次/分钟**（超限 `45011`） |
| 未上架 | 100 次/天（`10060`） |
| 提额 | 走服务商平台 `https://fuwu.weixin.qq.com`（同主体限制），单次提额包示例 10 万/分钟 |

> 多端 用户端量级下免费额度通常足够；提额仅在登录峰值或营销活动时考虑。

### 3.8 个人主体 / 个人开发者的资质边界（关键卡点）

> 结论：个人主体**无法完整达成「四端 + unionid 打通」**，只能实现「无 unionid 的单端登录」。

**分端判定**：

| 端/机制 | 个人主体能否达到 | 关键依据 |
|---------|:--:|---------|
| 小程序一键登录 | ✅ 能（单端） | 个人主体可注册小程序；`wx.login`→`code2Session` 拿 openid 即可登录，**无需开放平台** |
| 移动应用拉起登录 | ⚠️ 基本能（有条件） | 个人可创建移动应用；未认证上架可「软著 + 手持身份证」替代 |
| 网站应用扫码登录 | ❌ 基本不能 | 《网站信息登记表》**需加盖公章**（个人无公章）+ ICP 备案官网 + 主体一致 + 部分类目强制企业认证 |
| 公众号网页授权 | ❌ 不能 | 个人只能注册订阅号，订阅号无网页授权、无法生成带参二维码 |
| 跨端 unionid 打通 | ❌ 不能完整达成 | 需开放平台「开发者资质认证」实质面向企业/组织，且网站应用环节被《登记表》公章卡死 |

**三个关键卡点**：

1. **网站应用是硬门槛**：《登记表》要求「公章与主办单位/认证主体一致」，个人无公章（仅港澳/海外主体开「有权人手写签名」口子，大陆个人主体不在豁免之列）；官网还需可访问 PC 站点 + ICP 备案 + 主体一致。
2. **部分类目强制企业认证**：「部分应用类目须完成开发者资质认证（企业认证）后才可选（类目分个人/非个人）」，教育类大概率落「非个人」类目。
3. **个人订阅号无网页授权**：「网页授权需已认证服务号，个人订阅号不支持」「带参二维码必须服务号」（报 `48001`）。

**个人开发者能达到的上限**：小程序一键登录 + 移动应用拉起登录的**单端能力**（只拿 openid，无 unionid），两端账号隔离、数据无法互通；且移动应用未上架每日限 100 次。

## 四、各工程约束与改造分析

### 4.1 tpl-app-api（后端配套）— 改造量最大

**现状**：Spring Boot 3.2.5 + Sa-Token JWT，仅有密码登录（`POST /auth/login` grantType=password/sms）；**无 JustAuth、无社交登录、无微信接口封装**。`sys_social` 表已存在（共享库，含 `open_id`/`union_id`/`source` 等字段）但未被本工程使用。

**需改造（建议方向，非实现）**：

3. **账号绑定/自动注册逻辑**（对应既有设计文档 §3.2.3「5b 未绑定」场景）：
   - 按 `unionid` → 再按 `openid` 查 `sys_social` 定位用户；
   - 命中 → 直接 `StpUtil.login` 签发 token；
4. **`sys_social` 写入**：登录/绑定时写入 `source`（`wechat_open`/`wechat_mp`/`wechat_xcx`）、`open_id`、`union_id`、`nick_name`、`avatar`（头像 URL 自存）。
5. **微信授权变更回调端点**：接收消息推送（`user_authorization_revoke` 等），删除/匿名化本地绑定与用户数据（合规硬性要求，见 §三.6）。
6. **头像自存**：微信 `headimgurl` 会失效，须下载转存 MinIO，`sys_user.avatar` 存自存路径。
7. **配置项**：`wechat.xxx`（appId/secret/redirectUri）入环境变量，与 RSA/JWT 密钥同治理标准（对齐宪法原则 9）。

## 五、跨端账号统一（多端账号打通设计）

### 5.1 两套独立的账号体系

| 体系 | 应用（开放平台） | 后端 | 用户群 | 是否需 unionid 打通 |
|------|----------------|------|--------|:--:|
| 用户端 | 1 网站应用 + 1 移动应用 + 1 小程序（同一开放平台账号） | tpl-app-api | 用户 | **是（四端互通）** |
| 管理端 | 1 网站应用（独立，或独立开放平台账号） | tpl-manage | 管理员 | 否（与用户隔离） |

### 5.2 隔离的本质：openid 按 AppID 隔离

```
openid  = 微信用户 + 单应用 AppID     （每应用不同）
unionid = 微信用户 + 开放平台账号      （同一账号下所有应用相同）
```

- 移动应用和小程序是两个不同的 AppID，同一微信用户在两端得到**两个无关联的 openid**；后端拿 openid 当身份锚点，就拆成两个 `sys_user` 账号。
- **隔离边界 = AppID 边界**：Android 与鸿蒙共用一个移动应用 AppID → openid 相同 → 不隔离；移动应用 ↔ 小程序 AppID 不同 → 隔离。
- 微信**不提供 openid 互查接口**，两个 openid 之间唯一的关联桥梁是 unionid（或业务侧自建锚点，如手机号）。

### 5.3 打通方案对比

| 方案 | 是否彻底打通 | 用户操作 | 工程复杂度 | 主体要求 |
|------|:--:|------|:--:|------|
| **A. unionid**（绑开放平台） | ✅ | 登录即识别，零额外操作 | 低（改查表锚点） | 企业认证 + 绑定 |
| **B. 手机号关联**（事后合并） | ⚠️ 脆弱 | 每次授权手机号，可拒绝 | 高（账号合并 + 换绑） | 个人可 |
| **C. 手机号主键 + openid 凭证**（双端绑定） | ✅ | 首次双重授权 | 中 | 个人可 |
| 单端绑定微信 | ❌ | — | — | —（openid 对不上） |

### 5.4 方案 A：unionid（推荐，需企业主体）

```
同一微信开放平台账号
  ├── 网站应用（tpl-app-web 扫码）   ┐
  ├── 移动应用（tpl-app-android/harmony 拉起） ├── 同一用户 unionid 唯一
  └── 小程序（tpl-app-mini 一键，绑定到开放平台）┘
```

- 后端 `sys_social` 以 `union_id` 作为跨端主锚点、`open_id` 作为单应用锚点；
- 登录匹配顺序：**unionid → openid → 新建/引导绑定**；
- 若开放平台账号不一致，则同一微信用户在四端会是**四个独立账号**（数据无法互通），属于产品级失败风险，须在申请阶段就锁定「统一开放平台账号」。

### 5.5 方案 C：手机号主键 + openid 凭证（个人主体可行，当前阶段落地方向）

> 核心：本系统「手机号即用户名」，天然可用**手机号作为跨端账号主键**；微信 openid 降级为「挂在账号上的快捷登录凭证」，存 `sys_social`（`source` 区分 `wechat_open` / `wechat_xcx`）。**无需 unionid，个人主体可落地。**

**小程序端（tpl-app-mini）**：

```
微信一键登录 → wx.login → openid=oMini
   ↓ 查 sys_social by open_id=oMini
   ├─ 命中 → 直接登录（无需再要手机号）
   └─ 未命中（首次）→ 要求授权手机号 → phoneNumber
        ↓ 查 sys_user by phone_number
        ├─ 有 → 写 sys_social{user_id, source=wechat_xcx, open_id=oMini} → 登录
        └─ 无 → 建 sys_user{phone} + sys_social{...} → 登录
```

**安卓/鸿蒙端（tpl-app-android / tpl-app-harmony）**：

```
手机号注册/登录（主流程）→ 个人中心「绑定微信」→ 拉起授权 → oMobile
   → 写 sys_social{user_id, source=wechat_open, open_id=oMobile}
之后「微信登录」→ oMobile → 查 sys_social → 命中 → 登录；未命中 → 提示先手机号登录后绑定
```

**边界与代价（必须知晓）**：

| # | 边界 | 说明 |
|---|------|------|
| 1 | 小程序首次登录是**双重授权** | 微信授权 + 手机号授权；拒绝手机号 = 无法登录（硬前提） |
| 2 | 换手机号需**换绑** | 两端同步更新，旧微信绑定关系跟随 |
| 3 | 一个账号可绑多个微信 | 需明确「手机号账号最多绑几个微信」 |
| 4 | 隐私合规 | 用手机号做跨端身份关联，需隐私政策告知 + 用户同意 |
| 5 | 手机号只**首次**获取 | openid 命中后直接登录，不再每次弹手机号授权 |

> 方案 B（手机号关联·事后合并）因需账号合并、且授权可被拒绝，仅作兜底，不展开。

#### 8.2.5 登录流程

**social 策略（网站扫码 + 移动拉起）**：
```
1. SocialLoginBody 校验（source/socialCode/socialState 非空）
2. WechatAuthUtils.loginAuth(source, socialCode, socialState)
   → 网站: code → sns/oauth2/access_token → AuthUser{uuid=openid, unionId, nickname, avatar}
   → 移动: 同上（同一接口 sns/oauth2/access_token，仅 appid/scope 不同）
3. authId = source + uuid；sysSocialService.selectByAuthId(authId)
   ├─ 命中 → 取 userId → StpUtil.login(userId) → 返回 token
   └─ 未命中 → 返回「未绑定」+ { source, openId=uuid, unionId, nickname }（code 特殊业务码）
              前端引导：手机号登录后绑定（POST /auth/social/callback），或注册
```
> 差异点：RVP 未绑定直接报错「你还没有绑定第三方账号」；本系统改为返回「未绑定」状态 + openid，由前端引导走「手机号主键」关联（§五.5），避免纯绑定制与「微信一键登录/注册」的产品目标冲突。

**xcx 策略（小程序一键登录）**：
```
1. xcxCode → jscode2session → { openid, session_key, unionid? }
2. authId = "wechat_xcx" + openid；selectByAuthId(authId)
   ├─ 命中 → StpUtil.login(userId) → 返回 token
   └─ 未命中 → 需 phoneCode（前端 getPhoneNumber）→ getuserphonenumber → phoneNumber
              → 按 phoneNumber 查 sys_user：有 → 绑定 openid 到该 userId；无 → 建号 + 绑定
```
> `session_key` 仅服务端保存（Redis/不落库明文），不下发前端。

> **无密码账号**：xcx 策略「无 → 建号」创建的账号**无密码**（`sys_user.password` 为空字符串）。相关约束：
> 1. 密码登录**拒绝**无密码账号（返回「该账号未设置密码，请使用微信登录」）；
> 2. 修改密码时无密码账号**免校验当前密码**（当前密码传空即可提交，设置后转为普通账号）；
> 3. 后端提供 `GET /system/user/isEmptyPassword`（需 Token）供前端判断当前账号是否无密码、是否隐藏「当前密码」表单项。

**绑定（POST /auth/social/callback，需 Token）**：完全对齐 RVP `SysLoginService.socialRegister`——`authId = source + uuid`，`selectByAuthId` 非空则报「此三方账号已被绑定」，否则按 `userId + source` 插入/更新 `sys_social`（含 unionId、nickName、avatar）。

#### 8.2.6 数据模型（复用 sys_social，零 DDL）

- `sys_social` 表已存在（`sql/001-init-sys.sql`），字段 `auth_id`/`source`/`open_id`/`union_id`/`access_token`/`refresh_token`/`nick_name`/`avatar` 等，**无需新增表或改 DDL**。
- `source` 取值：`wechat_open`（网站）、`wechat_app`（移动）、`wechat_xcx`（小程序）。
